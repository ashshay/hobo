# Hobo 卡片交互动效优化方案

> 范围：信息流 / 详情 / 评论里的「卡片」及其内部元素。
> 明确不动：顶栏、底栏 dock（你说的 Docker）、页面转场、下拉刷新药丸、看图页手势。
> 基线：1.01.0+2；`prism_ui` 仍是 FlClash 仓库里的 path 依赖（见 `HOBO-项目状态与操作要求.md` §2.3）。

## 0. 一句话

不加新依赖、不改共享插件，用「按压缩放 + 心形填充 + 数字滚动 + 图片按压」四件事，把卡片从"点下去没反应"改成"每一处都有回应"，全部落在 90–350ms，只动 transform/opacity/color。

## 1. 现状核对（以代码为准）

| 交互 | 现在实际发生什么 | 问题 | 位置 |
| --- | --- | --- | --- |
| 点卡片 | `PressSurface(look: ink)`：10% 墨水叠加 + Android 触点亮斑，松开 200ms 淡出 | 200–600px 高的卡片上几乎察觉不到；没有位移 | `lib/ui/widgets/common.dart:326`、`prism_ui/lib/press_surface.dart:387` |
| 长按卡片 | 直接弹出 `showStatusActions` | 无触觉、无"按住"态 | `common.dart:336`、`lib/ui/routes.dart:273` |
| 点赞 | 图标在 `like` / `likeOutline` 之间硬切，数字直接替换 | 无过渡，社交产品最关键的即时奖励感缺失 | `lib/ui/widgets/status_card.dart:747` |
| 信息流点赞 | `StatusList` 根本没传 `onLike` | 卡片上的赞按钮**点了没反应**，只有详情页能赞 | `lib/ui/widgets/feed_list.dart:266`、`lib/ui/pages/feed_page.dart:358` |
| 评论点赞 | 同样是图标硬切 | 同上 | `lib/ui/widgets/comment_tile.dart:105` |
| 图片 / 视频 / 大图 | 裸 `GestureDetector`，图片有 Hero | 按下零反馈，误触感强 | `status_card.dart:405 / 476 / 508 / 578` |
| 转发块 | 裸 `GestureDetector` | 同上 | `status_card.dart:638` |
| 列表项 | `ListView.builder`，item 没有 key | 刷新/插入后按位置复用 State，动画、图片、按压态可能串到别的微博上 | `feed_list.dart:246` |
| 操作栏 | 图标 17px + 12px 文字，纵向 padding 4 | 命中区约 21px 高，远低于 48dp 最小触控，动画容易"打空" | `status_card.dart:803` |

一个额外事实：`WeiboText` 已经把富文本解析结果按 html/style 缓存（`weibo_text.dart:128`），所以点赞引发的整卡 rebuild 不会重新解析正文——这是可以放心做"点赞后重建卡片"的前提。

## 2. 动效语言（先定规矩，再谈实现）

| 层级 | 用在哪 | 时长 | 曲线 | 只动 |
| --- | --- | --- | --- | --- |
| L1 按压 | 卡片、图片、操作图标按下 | 进 90ms / 出 140ms | `easeOutCubic` | transform |
| L2 状态 | 点赞、收藏翻转 | 350ms 填充 + 1.1 峰值 pop | `easeInOutCubic` | color + transform |
| L3 数值 | 赞/评论/转发数变化 | 180ms | `easeOutCubic` | transform + opacity |
| L4 页面 | 页面转场、顶栏、dock | 不改 | — | — |

三条硬约束：

1. **只动 transform / opacity / color**，不动 width/height/padding，避免滚动列表里触发布局。
2. **跟手优先**：L1 在按下当帧就响应；手指移动超过 10px（比 `kTouchSlop` 的 18px 更早）立即回弹，避免"黏住"。
3. **`MediaQuery.disableAnimations` 时全部降为 0ms 终态**，功能不变。prism 已有 `context.disableAnimations` / `context.motionDuration()` 可用。

## 3. 分项设计

### 3.1 卡片按压（P0，核心）

**做法**：新增 `PressScale`（`lib/ui/widgets/card_motion.dart`），包住 `StatusCard` 的整张卡。

| 项 | 值 |
| --- | --- |
| 缩放 | 1 → 0.985（约 1.5%，200px 高的卡 ≈ 3px） |
| 进 | 90ms `easeOutCubic`，按下即开始 |
| 出 | 140ms `easeOutCubic`，松手/取消 |
| 取消 | 指针移动 > 10px，或 `PointerCancel` |
| 手势 | 只挂 `Listener`，**不进手势竞技场**，不与 `PressSurface` 的 tap、长按、列表滚动竞争 |

**为什么不换掉 prism 的 ink**：`PressLook.tint` 在浅色模式下是把整块面淡到 75% 不透明度（`card_surface.dart:195`），对一整张卡片太抢眼；ink 的 10% 叠加 + 缩放刚刚好。星点亮斑保留，是 prism 的辨识度。

**为什么 `RepaintBoundary` 要放在缩放的内层**：

```dart
PressScale(              // Transform 在最外
  child: RepaintBoundary( // 卡片已栅格化，缩放只变换这一层
    child: StatusCard(...),
  ),
)
```

缩放时 Flutter 复用卡片已画好的图层，不重绘正文和图片。

**已知取舍**：`Listener` 不知道子级手势，点操作栏图标时整卡也会缩一下。1.5% 下基本不可见，且和图标回弹是同向的，可以接受。若实测不能接受，走 §6 的备选 A。

### 3.2 点赞（P0 接线 + P1 动效）

**视觉**：描边心 → 实心红心，350ms 由外向内填充 + 峰值 1.1 的 pop。

prism 已有现成实现 `AnimatedGlyph`（`prism_ui/lib/icons/animated_glyph.dart`）：它把 `Glyph` 的 body 路径在 `fill=0` 时按 1.8 描边画成轮廓，`fill→1` 时描边从 `_fillStart` 一路加粗到填满，同时叠一个 `sin` 的 10% 缩放。`HoboGlyphs.like` 的路径本来就是实心心形，正好符合这个机制，**不需要新画图标、不需要 Lottie**。

| 项 | 值 |
| --- | --- |
| 填充 + pop | 350ms，`easeInOutCubic`（prism 内置） |
| 颜色 | 直接切 `colorScheme.error`，不做补间（Twitter 也是瞬间变色） |
| 触觉 | `HapticFeedback.lightImpact()`，仅"点赞"方向 |
| 数字 | 上滑 8px + 淡入，180ms（见 3.6） |

**必须一起做的接线**（否则信息流里根本没有点赞入口，动效无从谈起）：

- `StatusList` 增加 `onLikeStatus`，`StatusCard.onLike` 透传。
- 新增 `toggleStatusLike(context, controller, status)` 放 `lib/ui/routes.dart`：
  1. 未登录 → banner「登录后才能点赞」，不动画；
  2. 乐观翻转 `status.copyWith(liked: next, attitudes: ±1)` → `controller.replace()`；
  3. `await repo.like(id, liked: 旧值)`（注意这个 API 传的是**翻转前**的状态，见 `repo.dart:1423`）；
  4. 失败 → `replace(原值)` 回滚 + 错误 banner。
- 在途去重：同一 `id` 请求没回来前忽略后续点击。`repo.like` 自带 1s 冷却，会抛「点得太快了」——这个提示不应该因为用户手快就弹出来。

### 3.3 收藏 / 转发 / 评论（P1）

- **收藏**：同样用 `AnimatedGlyph(glyph: bookmark)`，颜色 `primary`。
- **转发 / 评论**：不改图标，图标做 1 → 0.88 → 1 的 120ms 回弹（复用 `PressScale`）。
- **命中区**：`_ActionButton` 从「图标 + 文字自然高度」改成最小 40px 高、`Center` 居中，`HitTestBehavior.opaque` 保持。这是可用性修复，不配合放大会让动效"点不到"。
- **语义**：顺手给 `_ActionButton` 包 `Semantics(button: true, label: '赞 12', onTap: ...)`。现在是裸 `GestureDetector`，读屏只会念出数字。

### 3.4 图片 / 视频 / 大图（P1）

- `PressScale(scale: 0.97)` 放在 **`Hero` 的 child 位置**：`Hero(tag, child: PressScale(child: Stack[图, 压暗层]))`。这样 Hero 量到的仍是未缩放的矩形，flight 的起止尺寸不受影响。
- 压暗层和图一起缩放，LIVE / 播放键这类徽标留在 `PressScale` 外面，不跟着缩。
- 压暗 4% 用 `Stack` 里叠一层 `ColoredBox` + `Color.lerp` 驱动；不要用 `AnimatedOpacity`（会 `saveLayer`，图片层很贵）。
- 视频没有 Hero（`_VideoBlock`），直接把 `PressScale` 包在它的 `Stack` 外即可。

### 3.5 转发块（P2）

不缩放（内容高度大、有文字，缩放会糊）。改成用 prism 的 `PressSurface` 直接替换裸 `GestureDetector`：

```dart
PressSurface(
  fill: surfaceContainerHigh.withValues(alpha: 0.6),
  shape: AppShape.all(AppCorner.md),
  padding: const EdgeInsets.all(10),
  onPressed: onOpen,
  child: ...,
)
```

白拿 ink、焦点环、键盘激活、无障碍语义，且因为 `_childClaimed` 的存在（`card_surface.dart:612`），点转发块时外层卡片的按压会被自动跳过，不会两层一起亮。

### 3.6 数字滚动（P2）

`CountRoll`：`AnimatedSwitcher` + `SlideTransition(0, 0.3 → 0)` + `FadeTransition`，180ms，`child` 用 `ValueKey(value)`。

只在挂载后数值变化时触发（首次构建不动画）。数字位数变化时 `AnimatedSwitcher` 按最大子项占位，宽度不会再跳；若觉得仍在挤，外套 `AnimatedSize`。

### 3.7 长按（P0，一行）

`HoboCard` 的 `onLongPress` 前加 `HapticFeedback.mediumImpact()`。长按期间手指没抬，`PressScale` 会一直保持 0.985，天然就是"按住"态；松手回弹，菜单由 prism 自己的 sheet 转场负责。

### 3.8 明确不做

| 不做 | 原因 |
| --- | --- |
| 列表错峰入场动画 | 与 `scroll_anchor.dart` 冷启动落位、下拉刷新冲突；滚动中重建会闪 |
| Lottie / Rive | 为一个点赞引入 +2MB 包体和资源管线，不值 |
| 整卡 tint 闪烁 | 25% 透明度变化在大卡片上太抢 |
| 点赞粒子爆炸 | 性能不划算；要"更爽"用 P3 的光环（径向渐变 scale+fade）替代 |
| 双击图片点赞 | 微博用户没有这个习惯，容易误触 |
| 卡片→详情的共享元素转场 | 要改 prism 全局 `page_transition`；整卡 Hero 会和九宫格里已有的图片 Hero 抢 tag，收益不抵风险 |
| 顶栏 / dock / 页面转场 / 下拉刷新 | 本轮范围外 |

## 4. 关键实现骨架

### 4.1 PressScale

```dart
class PressScale extends StatefulWidget {
  const PressScale({
    super.key,
    this.scale = 0.985,
    this.enabled = true,
    required this.child,
  });

  final double scale;
  final bool enabled;
  final Widget child;

  @override
  State<PressScale> createState() => _PressScaleState();
}

class _PressScaleState extends State<PressScale>
    with SingleTickerProviderStateMixin {
  static const _down = Duration(milliseconds: 90);
  static const _up = Duration(milliseconds: 140);
  static const _cancelSlop = 10.0;

  late final _press = AnimationController(
    vsync: this,
    duration: _down,
    reverseDuration: _up,
  );
  late final _curve = CurvedAnimation(parent: _press, curve: Curves.easeOutCubic);

  int? _pointer;
  Offset? _origin;

  @override
  void dispose() {
    _curve.dispose();
    _press.dispose();
    super.dispose();
  }

  bool get _active => widget.enabled && !context.disableAnimations;

  void _onDown(PointerDownEvent event) {
    if (!_active || _pointer != null) return;
    _pointer = event.pointer;
    _origin = event.position;
    _press.forward();
  }

  void _onMove(PointerMoveEvent event) {
    if (event.pointer != _pointer) return;
    if ((event.position - _origin!).distance > _cancelSlop) _release();
  }

  void _release() {
    if (_pointer == null) return;
    _pointer = null;
    _origin = null;
    _press.reverse();
  }

  @override
  Widget build(BuildContext context) {
    return Listener(
      onPointerDown: _onDown,
      onPointerMove: _onMove,
      onPointerUp: (_) => _release(),
      onPointerCancel: (_) => _release(),
      child: AnimatedBuilder(
        animation: _curve,
        builder: (context, child) => Transform.scale(
          scale: 1 - (1 - widget.scale) * _curve.value,
          child: child,
        ),
        child: widget.child,
      ),
    );
  }
}
```

### 4.2 心形与数字

```dart
class LikeHeart extends StatelessWidget {
  const LikeHeart({super.key, required this.liked, this.size = 17});

  final bool liked;
  final double size;

  @override
  Widget build(BuildContext context) {
    final color = liked
        ? context.colorScheme.error
        : context.colorScheme.onSurfaceVariant;
    return IconTheme.merge(
      data: IconThemeData(color: color, size: size),
      child: context.disableAnimations
          ? GlyphIcon(liked ? HoboGlyphs.like : HoboGlyphs.likeOutline)
          : AnimatedGlyph(glyph: HoboGlyphs.like, filled: liked),
    );
  }
}
```

### 4.3 列表接线

```dart
// feed_list.dart
final status = controller.items[itemIndex];
return Padding(
  padding: const EdgeInsets.only(bottom: 10),
  child: PressScale(
    child: RepaintBoundary(
      child: StatusCard(
        key: ValueKey(status.id.isEmpty ? 'i$itemIndex' : status.id),
        status: status,
        onLike: widget.onLikeStatus == null
            ? null
            : () => widget.onLikeStatus!(status),
        // ...其余透传不变
      ),
    ),
  ),
);
```

`ValueKey` 用 `id`，空 id 时退回下标（否则多条空 id 会撞 key 直接崩）。

## 5. 性能与无障碍

- **帧预算**：prism 的规矩是 120Hz 下 UI 工作 ≤8ms。本方案每帧新增的只有一个 `Transform` 和一个 350ms 的 `CustomPaint`（点赞那颗心，`shouldRepaint` 只在 fill/color 变时为真）。
- **不新增 saveLayer**：图片压暗用换色 `ColoredBox`，不用 `Opacity`。
- **重建范围**：点赞会触发 `FeedController.replace` → 整个可视列表 rebuild；靠 key + `RepaintBoundary` 把重绘限制在单卡。`WeiboText` 已有 span 缓存，rebuild 不重新解析 HTML。
- **离屏**：`ListView` 直接销毁离屏 item，不需要额外 `TickerMode` 处理。
- **无障碍**：`disableAnimations` 全降 0ms；操作按钮补 `Semantics(button: true)`；触觉只在点赞/长按，不滥用。

## 6. 风险与备选

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 点操作栏图标时整卡缩放 | 轻微双重反馈 | 1.5% 不可见，先接受；不行走备选 A |
| `AnimatedGlyph` 在 fill=0 时描的是实心路径的轮廓，可能与 `likeOutline` 有 1px 级差异 | 视觉不齐 | 现在 17px / 15px 两档和 `likeOutline` 并排比对；不齐就退回 `AnimatedSwitcher` 交叉淡入两枚图标 |
| 点赞重建可视列表 | 首帧可能超 8ms | 先 key + RepaintBoundary；仍有问题再上 per-item notifier（备选 B） |
| `repo.like` 1s 冷却 | 手快时弹「点得太快了」 | 在途去重，冷却期静默回滚 |
| 与 `HoboRefresh` 的 Listener 嵌套 | 无冲突 | 两者都只读指针事件，不进竞技场 |

**备选 A**：给 `prism_ui` 的 `PressSurface` 加 `pressScale = 1.0` 参数，在 `RenderCardSurface.paint` 里对 surface + child 一起缩放。优点是直接复用 `_childClaimed`（点子按钮不缩放）和 `_inScrollView`（滚动里延迟 150ms）；代价是动共享插件，要回归 FlClash，而且 `_press` 的 200ms 对缩放偏慢，还得再加曲线参数。**本方案默认不做**。

**备选 B**：`FeedController` 给每条 `Status` 配一个 `ValueNotifier`，列表只在数量变化时 `setState`，卡片用 `ValueListenableBuilder` 自更新。能彻底消掉点赞引发的全表 rebuild，但会改 `FeedController` 的对外契约（`items` 变成只读视图），影响 5 个调用方，P3 再评估。

## 7. 实施顺序

| 阶段 | 内容 | 涉及文件 | 预估 |
| --- | --- | --- | --- |
| P0 | `PressScale` + 卡片接入 + item key + 长按触觉 | `card_motion.dart`(新)、`status_card.dart`、`feed_list.dart` | 0.5 天 |
| P0 | 信息流点赞接线 + 在途去重 + 乐观回滚 | `routes.dart`、`feed_list.dart`、feed/profile/search/nearby | 0.5 天 |
| P1 | `LikeHeart` / 收藏图标 / 操作栏命中区与语义 | `status_card.dart`、`comment_tile.dart` | 0.5 天 |
| P1 | 图片、视频、大图按压 + 压暗 | `status_card.dart` | 0.5 天 |
| P2 | 数字滚动、转发块换 `PressSurface`、详情页同步 | `status_card.dart`、`comment_tile.dart`、`detail_page.dart` | 0.5 天 |
| P3 | per-item notifier、点赞光环（可选） | `feed_list.dart`、repo 层 | 1 天 |

P0–P2 合计约 2.5 天。**注意 P0 里的「信息流点赞接线」严格说不是动画**，但没有它，信息流里的点赞动效永远不会被触发。如果你只想改动画、不想新增功能，这条可以砍掉，只保留详情页与评论区的点赞动效。

## 8. 验收清单

1. 快速上滑：卡片不缩放；按下后拖 >10px：回弹且无残留。
2. 点卡片进详情：按下有收缩，返回后卡片恢复正常尺寸。
3. 信息流点赞：心形 350ms 填充 + 1.1 pop + 数字上滑 + 轻震；再点取消：回描边、数字下滚、无 pop。
4. 连点 5 次：不弹「点得太快了」，最终状态与服务器一致。
5. 断网点赞：动画播完 → 回滚 → 错误 banner。
6. 未登录点赞：只出 banner，不播动画。
7. 点评论 / 转发 / 更多：卡片不缩放，图标 0.88 回弹。
8. 点图片：0.97 收缩 + 压暗 → 松手进看图页，Hero 无跳变。
9. 长按卡片：中震 + 保持按住态 → 菜单弹出。
10. 系统开启「移除动画」：全部瞬时完成，功能不变。
11. `flutter analyze --no-fatal-infos` 0 error / 0 warning；`flutter test` 11/11。
12. `flutter run --profile` 抓 Timeline：点赞动画期间无 >16ms 帧。
