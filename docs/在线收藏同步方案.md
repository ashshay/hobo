# Hobo「在线收藏同步」可行性方案

> **状态：已落地并在雷电模拟器上跑通**（2026-11-27，见第 10 节）。读走 `weibo.com/ajax/favorites/all_fav`，
> 写走 `weibo.com/ajax/statuses/createFavorites|destoryFavorites`；`containerid=230267` 已被微博掏空，
> 实测只回「这里还没有内容」，当初方案里把它当读接口是错的。
>
> 结论先说：**能。** 但要把「同步」拆成两件事——**从微博把收藏拉下来**（只读，风险极低）和**把本地收藏写回微博收藏夹**（要正确的 weibo.com ajax 接口 + XSRF，有风控）。
>
> 另有第三条路：**不碰微博接口**，把 `favorites.json` 整表同步到自建存储（WebDAV / Gist / 自建 Worker）。多设备「收藏还在」这个需求用它最稳，完全离线可用，也不吃账号风控。

历史参考：Cobo 1.1.19 之前收藏是**只读**的在线容器 `containerid=230267`（`cobo-v119/.../Repo.kt:1667`），后来在 `942a152 feat(feed,ui): 新增本地收藏…` 里改成本地实现。原因写在 `cobo-v119/docs/03-功能清单.md:33,58`：

- 收藏列表 ✅ `containerid=230267`
- 收藏/取消收藏动作 ❌ `api/favorites/create`、`destroy` 均 404 —— 「只能查看收藏列表」

**那次失败的关键是打错了站**：`m.weibo.cn` 的 `api/favorites/*` 不存在；真正能写的是 `weibo.com` 的 `/ajax/favorites/*`。下面第 3 节有跑通过的调用形态。

## 2. 三条路，选哪条

| | 方案 A：和微博收藏夹双向同步 | 方案 B：自建云同步 | 方案 C：只读在线镜像 |
| --- | --- | --- | --- |
| 目标 | 和网页版/官方 App 的收藏互通 | 只有本 App 的多设备一致 | 先把在线收藏显示出来 |
| 依赖 | 微博 `weibo.com` ajax + XSRF + 风控 | WebDAV/Gist/自建 KV | 微博只读接口 |
| 离线 | 队列 + 墓碑，稍复杂 | 整表读写，天然离线 | 无（只能读时在线） |
| 风险 | 写接口被风控、分组语义不明 | 需要用户给存储凭据 | 几乎没有 |
| 工作量 | 2～3 天（含真机验证） | 1～2 天 | 0.5～1 天 |

推荐路线：**先 C 打通只读（顺手验证接口）→ 再 A 补写回**；如果用户的实际诉求只是「换手机别丢收藏」，直接上 **B**，别跟微博风控较劲。

## 3. 微博侧接口（有据可查的调用形态）

同机的参考实现 `D:\coding\repos\Android_16_Weibo` 里这几个端点是被使用中的（`app/src/main/java/com/example/myweibo/data/WeiboEndpoints.kt:9-13`）：

```
GET   /ajax/favorites/all_fav            # 读：我的收藏
POST  /ajax/statuses/createFavorites     # 写：收藏（注意官方拼写不是 createFavorite）
POST  /ajax/statuses/destoryFavorites    # 写：取消收藏（官方就是把 destroy 拼成 destory）
```

调用约定（`WeiboWebSession.kt:1418-1448`、`:1254-1263`）：

- Host `https://weibo.com`，**桌面 Chrome UA**
- `Referer: https://weibo.com/fav`，`X-Requested-With: XMLHttpRequest`，`Origin: https://weibo.com`
- Cookie 必须是 `weibo.com` 域那份（`SUB` / `SUBP` / `XSRF-TOKEN`）
- 额外头 `X-XSRF-TOKEN` = cookie 里 `XSRF-TOKEN` 的 **URL 解码值**
- 读：`?uid=<uid>&page=<1..n>`，响应里微博挂在 `data.statuses` / `data.list` / `data.favorites`，条目可能包一层 `mblog`
- 写：`Content-Type: application/json`，body `{"id":"<数字 status id>"}`（不是 mblogid），成功判定 `ok == 1` 或 `data` 存在

Hobo 侧的前置能力**已经齐了**，不用新加依赖：

- `Api.getDesktop()`（`lib/data/api.dart:139`）就是按桌面浏览器签名的 GET
- `Api.postDesktopJson()`（`lib/data/api.dart:156`）支持传 `xsrfToken`
- `CookieVault.desktopAuthHeader(cookies, 'weibo.com')`（`lib/data/cookie_vault.dart:154`）
- `CookieVault.cookieValue(cookies, 'weibo.com', 'XSRF-TOKEN')`（`lib/data/cookie_vault.dart:188`）
- `Session.cookies` 是「域名 → cookie 行」表，`.weibo.com` 那份是网页登录时一起种下的

唯一的小硬伤：`Api.getDesktop` / `postDesktopJson` 把 `Referer` 写死成 `https://weibo.com/`，收藏接口最好带 `https://weibo.com/fav`。给这两个方法加一个可选 `referer` 参数即可（默认值不变，零回归）。

**待真机确认的三件事**（别假设，验一次就够）：

1. `all_fav` 实际返回键名是 `data.statuses` 还是 `data.favorites`；
2. `createFavorites` 不带分组时是否落进默认分组，返回体是 `{"ok":1}` 还是 `{"data":{...}}`；
3. 连续写多少条会触发 `20016`（update weibo too fast）——决定全量对齐的限速。

## 4. 方案 C：只读在线镜像（第一步）

改动最小，能立刻回答「接口还活着吗」。

```dart
// lib/data/favorites_sync.dart（新增）
// 下面两段都写在 Repo 里（或作为 Repo 的 extension），这样才能直接用
// session / ownUid() / store 这些成员；单独建类的话把这些当参数传。
const _favList = 'https://weibo.com/ajax/favorites/all_fav';

Future<List<Status>> remoteFavorites({int maxPages = 20}) async {
  final active = session;
  if (active == null || !active.loggedIn) {
    throw ApiException('纯本地模式看不了在线收藏，登录后可用');
  }
  final uid = await ownUid();
  final cookie = CookieVault.desktopAuthHeader(active.cookies, 'weibo.com');
  final out = <Status>[];
  for (var page = 1; page <= maxPages; page++) {
    final root = await Api.getDesktop(
      Api.url(_favList, {'uid': uid, 'page': '$page'}),
      cookie.isEmpty ? active.cookie : cookie,
    );
    final data = root.obj('data');
    final arr = data?.arr('statuses') ??
        data?.arr('favorites') ??
        data?.arr('list') ??
        root.arr('statuses');
    var got = 0;
    for (final entry in arr ?? const []) {
      final o = jObj(entry);
      if (o == null) continue;
      final mblog = o.obj('mblog') ?? o.obj('status') ?? o;
      final status = Status.from(mblog);
      if (status == null) continue;
      out.add(status.copyWith(favorited: true));
      got++;
    }
    if (got == 0) break;
    if (!(data?.boolean('has_more') ?? false) && got < 20) break;
  }
  return out;
}
```

接线（C 档）：

1. `FavoritesPage` 底部加下拉刷新，刷新时 `await repo.syncFavorites()`；
2. `repo.favorites()` 在「已登录 + `settings.favoritesOnline`」时先返回内存里的在线镜像，再回落到 `store.favorites()`；
3. 界面在来源不同的条目上加个小标记（`在线` / `本机`），避免误导；
4. 纯本地模式 / 未登录：**行为完全不变**。

C 档不写任何东西，最坏情况就是「刷新失败」，没有数据风险。

## 5. 方案 A：双向同步的设计

### 5.1 数据模型

`favorites.json` 继续当缓存 + 离线队列，新增一份 per-account 的同步状态（因为**服务器收藏是按账号的，本地收藏是全局的**，这是唯一的模型冲突点）：

```json
// favorites_sync_<uid>.json
{
  "uid": "1234567890",
  "lastSyncAt": 1700000000000,
  "items": {
    "5000000000000001": { "state": "synced",  "at": 1700000000000 },
    "5000000000000002": { "state": "pending_add", "at": 1700000000100 },
    "5000000000000003": { "state": "pending_del", "at": 1700000000200 },
    "5000000000000004": { "state": "dead" }
  },
  "tombstones": { "5000000000000005": 1700000000300 }
}
```

- `state=synced`：两边都有
- `pending_add`：本地新增，还没写回服务器
- `pending_del`：本地删了，还没从服务器删
- `dead`：微博已删/不可见，永远不再重试
- `tombstones`：本地删除的时间戳，**优先于**服务器仍存在的事实（用户显式动作不能被一次拉取覆盖）

条目本身怎么存？两种：`favorites.json` 保持全局（现状），同步器只维护「(uid, id) → state」。**不要**改成按账号分表——那会破坏现在「切号不丢收藏」的产品语义。

### 5.2 同步算法（一次 `syncFavorites()`）

```
1. 前置：已登录 && 开关打开；否则直接返回本地表
2. remote = remoteFavorites()   // 全量分页，页间隔 300~500ms
3. remoteIds = {remote.id}
4. 先还删除账（pending_del ∪ tombstones 中晚于 lastSyncAt 的）：
     for id in 上一步集合:
         POST destoryFavorites {id}
         成功 → 删墓碑、删 state；404/已不存在 → 同样清掉
5. 再还新增账（pending_add）：
     for id in pending_add - remoteIds:
         POST createFavorites {id}
         成功 → state=synced
         404 → state=dead
         too fast → 停手，记退避时间，本轮结束（保留 pending_add 下轮继续）
         每条之间 ≥ 1.5s（和 lib/data/like_gate.dart 同一套思路）
6. 拉下来的在线集合并入本地缓存：
     remote 有、本地无、且本地没有墓碑 → store.addFavorite(status)（镜像）
     remote 有、本地有 → 只是刷新一下快照
7. 反向收敛（可选，默认开）：
     本地 state=synced、remote 没有、且不是本轮刚加的 → 说明在网页/别的客户端取消了
     → 从本地缓存移除（或标记「已失效」）
8. lastSyncAt = now，落盘，favoritesVersion++，_notify()
```

冲突原则一句话：**同一条以「最后一次用户动作的时间戳」为准，本地墓碑胜出**。

### 5.3 触发时机

- 收藏页下拉刷新 → 全量 `syncFavorites()`
- 冷启动后第一次进收藏页 → 若距 `lastSyncAt` > 10 分钟，后台跑一次
- 点收藏/取消 → 立即单条写回（`favorite()` 里加一步）；失败就落 `pending_add/pending_del`，不打断 UI、不弹错，只在收藏页显示「N 条待同步」
- 切号 / 登出：同步器按 uid 换用 `favorites_sync_<uid>.json`，不同账号的队列不串

### 5.4 写回的具体代码形状

```dart
// lib/data/api.dart：给两个桌面方法加可选 referer（默认值不变）
static Future<Map<String, dynamic>> postDesktopJson(
  String target,
  String body, {
  String? cookie,
  String? xsrfToken,
  String referer = 'https://weibo.com/',   // 新增
}) { ... 'Referer': referer ... }

// lib/data/favorites_sync.dart
const _favCreate = 'https://weibo.com/ajax/statuses/createFavorites';
const _favDestroy = 'https://weibo.com/ajax/statuses/destoryFavorites';

Future<void> _writeRemote(String id, {required bool favorite}) async {
  final active = session!;
  final cookie = CookieVault.desktopAuthHeader(active.cookies, 'weibo.com');
  final raw = CookieVault.cookieValue(active.cookies, 'weibo.com', 'XSRF-TOKEN') ?? '';
  final xsrf = raw.isEmpty ? '' : Uri.decodeComponent(raw);
  final root = await Api.postDesktopJson(
    favorite ? _favCreate : _favDestroy,
    jsonEncode({'id': id}),
    cookie: cookie.isEmpty ? active.cookie : cookie,
    xsrfToken: xsrf,
    referer: 'https://weibo.com/fav',
  );
  final ok = root.intOf('ok', 0) == 1 || root.has('data');
  if (!ok) throw ApiException(root.str('msg', '收藏同步失败'));
}
```

### 5.5 坑清单（照这个顺序踩）

| 坑 | 处理 |
| --- | --- |
| `id` 用错 | 必须 `Status.id`（数字），不是 `Status.mid`（mblogid）。参考实现在 `WeiboApp.kt:7938-7941` 就是「先 id 再 statusId」 |
| UA / Referer 不对 → 直接回 visitor 页 | 走 `Api.getDesktop/postDesktopJson`，Referer 用 `https://weibo.com/fav` |
| 缺 `X-XSRF-TOKEN` | `weibo.com` 域 cookie 里取 `XSRF-TOKEN` 再 URL 解码；缺这份 cookie 说明只从 m 站登录过，需要引导去网页登录一次 |
| 432 / `ok:-100` | 已有 `_get()` 里访客 cookie 重试逻辑；写接口不适用，直接提示重新登录 |
| `20016 update weibo too fast` | 全量对齐限速 1 条/1.5s + 指数退避，遇错停手 5 分钟（复用 `like_gate.dart`） |
| 收藏上限 | 网页端收藏夹有条数上限，超限 create 可能「成功但不落库」。别在当前账号上跑全量前先确认剩余额度 |
| 已删/仅粉丝可见的旧收藏 | 拉取时可能整条消失。用墓碑 + `dead` 标记，不要反复重试 |
| 分组/标签 | 网页收藏夹有分组概念，`createFavorites` 是否会要求 `tag_id` 待验证。默认落默认分组，方案不承诺保留分组 |
| 跨账号模型冲突 | 服务器按账号、本地全局：只维护 `(uid, id) → state`，条目表保持全局 |
| 收藏页「一页到底」 | `favorites()` 现在返回 `cursor: null`；同步后仍建议全量镜像（≤500 条），不做服务端分页滚动，避免和本地排序打架 |

## 6. 方案 B：自建云同步（只解决「多设备」）

不改任何微博接口，`favorites.json` 本身就是一份可序列化的完整快照。

1. 设置页加「云同步」：WebDAV 地址 + 用户名 + 口令（或 GitHub Gist token + gist id，放 `SharedPreferences`，口令走 Android Keystore 更稳妥）；
2. 上传：`PUT <dir>/hobo-favorites-<uid>.json`，body = `{ "version": 1, "updatedAt": ts, "items": [Status.toJson()...] }`；
3. 下载：`GET`，按 `id` 合并，`updatedAt` 新的整表胜出（收藏是「集合」语义，逐条并集 + 墓碑足够，冲突概率极低）；
4. 冲突：本地有删除记录（墓碑）→ 删除优先，其余取并集；
5. 触发：收藏变更 5 秒防抖上传；进收藏页或冷启动拉一次；失败静默，设置页显示上次成功时间。

优点：不吃微博风控、离线可用、纯本地模式也能用（不绑账号）。缺点：用户要自己准备存储。

| `containerid=230267` 已经不是收藏夹 | `GET m.weibo.cn/api/container/getIndex?containerid=230267` → `{"ok":0,"msg":"这里还没有内容","data":{"cards":[]}}` |
| `all_fav` 能读，形态是 status 数组 | `GET weibo.com/ajax/favorites/all_fav?uid=…&page=1` → `{"ok":1,"count":20,"data":[{…,"mblogid":"RthDxlfel",…}]}` |
| 收藏能写 | `POST …/createFavorites` body `{"id":"5369795815407693"}` → `{"ok":1,"status":{…,"favorited":true}}`，随后 `all_fav` 第一条就是它 |
| 取消能写 | `POST …/destoryFavorites` → `{"ok":1,"status":{…,"favorited":false}}`，随后 `all_fav` 里查不到该 id |
| 失败也是 HTTP 400 + JSON | `{"ok":0,"message":"you have collected this status!"}` / `"not your collection!"` / `"暂无查看权限"` |
| 网页登录的会话常常没有 `XSRF-TOKEN` | `.weibo.com` 的 cookie 表初始只有 `SCF/SUB/SUBP/ALF/WBPSESS`；打一次 `GET https://weibo.com/` 后多出 `XSRF-TOKEN` |

据此落地 / 修正的实现：

- `lib/data/repo.dart`：`onlineFavorites()` 改读 `all_fav`（page 分页，20 条一页）；`setOnlineFavorite()` 第一次被 400/403 挡回来时补一次 XSRF 再重试，并把服务端 `message` 原样抛给界面（不再只显示「HTTP 400」）
- `lib/data/store.dart`：`addFavorites()` 整页批量落盘（逐条写会把 20 条各重写一遍 `favorites.json`）
- `lib/ui/pages/library_pages.dart`：收藏页登录态读在线收藏、下拉刷新 + 「刷新」/「加载更多」，纯本地模式退回本机星标；在在线收藏页点「取消收藏」会连服务器一起删
- `lib/ui/pages/detail_page.dart`、`lib/ui/routes.dart`、`lib/ui/widgets/status_card.dart`：收藏按钮改走 `repo.toggleFavorite()`（先本机、再写微博）
- `lib/ui/pages/settings_page.dart` + `lib/data/settings.dart`：开关「收藏同步到微博」（互动分组，默认开）
- `lib/data/api.dart`：`getDesktop` / `postDesktopJson` 支持自定义 `referer`（收藏接口要 `https://weibo.com/fav`）

模拟器上跑过的流程：收藏页拉出 20 条在线收藏（含本机没有的）→ 详情页收藏一条 → 服务端 `all_fav` 第一条变成它 →
收藏页里「取消收藏」→ 服务端列表里消失。开关关掉时只写本机（`favorites.json` 有、服务端没有）。
