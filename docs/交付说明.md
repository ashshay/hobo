### 顺带修的一处 prism_ui 缺陷

`plugins/prism_ui/lib/common_button.dart` 的 `_StyledButtonState._handleStates` 原本直接
`setState`。按钮的 `onPressed` 在 null / 非 null 之间切换时（例如「保存中」禁用保存键），
内部的 `PressSurface` 会在 `didUpdateWidget` 里推进状态，进而让按钮在**自己 build 的过程中**
被标脏，触发 `!_dirty` 断言、整页红屏。现在把这次重建推迟到帧末。不修的话，debug 包上
「保存图片 → 关闭看图页」必崩。

## 1.2 1.02 新增

| 功能 | 落点 |
| --- | --- |
| 换新图标 | 换成 IconKitchen 导出的那一套（深绿底 + 白色回环箭头 + 底部青色条带 + HOBO 字样）。方图 `assets/icon/hobo_icon.png`，`tool/make_icons.py` 从它生成 Android 各密度的两套位图 |
| 图标形状可切换 | 设置 → 外观 →「应用图标」：**圆角矩形 / 圆形**。两套位图分别挂在 `.IconRounded` / `.IconCircle` 两个 `activity-alias` 上，同一时刻只启用一个（`MainActivity` 的 `hobo/icon` 通道）；`.MainActivity` 不再挂 MAIN/LAUNCHER，桌面始终只有一枚图标 |
| 应用内图标 | `ui/widgets/app_icon.dart` 的 `HoboAppIcon`：同一张方图按设置的形状裁切，用在设置页那一行、选择弹层和关于页页头，跟桌面选的是同一个形状 |
| 版本号 | `1.02.0+4` |

> **为什么不用自适应图标**：Android 8+ 的 `adaptive-icon` 由启动器决定遮罩形状，应用改不了。
> 要让形状由 App 说了算，只能把两套形状都画进位图、再用 `activity-alias` 换桌面入口。
> 代价写在明处：桌面若坚持给旧式位图再套一层遮罩（Pixel Launcher 会，Launcher3 与多数国产桌面
> 不会），图标外面还会多一层系统形状；「跟随桌面主题形状」的能力也随之没有了。
>
> 雷电模拟器（Android 14 / Launcher3）实测：两个方向都切得过去，图标始终停在原格，
> 切换后还能从桌面正常启动（进程没有因 `setComponentEnabledSetting` 被杀）。

## 6. 已知问题

1. **模拟器上偶发整机卡死**：进程 0% CPU、不响应触摸，`dart` 侧无异常。Kotlin 版在同一台
   模拟器上正常，因此更像 Flutter 引擎在该模拟器图形栈上的问题。已做的规避：
   - 关闭 Impeller（`AndroidManifest.xml` 的 `EnableImpeller=false`）；
   - 去掉 Android 拉伸回弹（每帧 `ImageFiltered`）；
   - 图片按显示宽度 `cacheWidth` 下采样。
   仍未根因定位；下一步建议在真机上复现，并用 `flutter run --profile` + Timeline 抓帧。
2. **prism 的 `showSheet` 在本工程不可用**：弹层内容高于初始 detent 时停在 hold 状态，
   整块不接收点击。已把所有选项选择器改为 `showFloatingDialog` + `AlertDialog`（见
   `common.dart` 的 `showHoboChoices`）。
3. 发布、聊天、超话、投票只有代码走查，未做端到端操作验证（发布会在真实账号发内容）。
4. 更新检查的 `Updater.releasesUrl` 仍为空，检查更新固定返回「已是最新版本」。
5. **评论配图没有端到端验证**：解析逻辑有单测，但模拟器上没翻到带图评论；渲染复用正文的
   `PicGrid`，风险主要在接口字段（若某个接口版本换了字段名，需要补 `picsOf`）。
6. **点赞会被微博限流**：短时间连点会返回「操作频繁，请您稍后再试」，客户端按失败处理
   （回滚本地计数并提示），这是服务端策略，不是 bug。
